# run-anythingllm

## What is AnythingLLM
[AnythingLLM](https://github.com/Mintplex-Labs/anything-llm) is an open-source, all-in-one desktop/docker app for running a private ChatGPT-like assistant on top of your own documents and LLMs. It bundles a chat UI, a document ingestion + RAG pipeline, and a vector database, and lets you plug in different LLM providers (OpenAI, Ollama, LM Studio, etc.), embedding models, and vector DBs (LanceDB, Chroma, Pinecone, ...) without writing any code. It also supports MCP (Model Context Protocol) servers so the assistant can call external tools/agents.

This repo just holds docker-compose configs and notes for running AnythingLLM locally against a local Ollama instance, with and without MCP servers wired up.

## run by docker
* pull the image
```
docker pull mintplexlabs/anythingllm
```

* run with local Ollama, no MCP servers
```
docker-compose -f docker-compose.local.yml up
```

* run with my local docker-compose file (includes MCP setup)
```
docker-compose -f docker-compose.local.mcp.yml up
```

* run with Claude (Anthropic) as the chat model instead of Ollama
```
cp .env.example .env   # then fill in ANTHROPIC_API_KEY=sk-ant-xxxx
docker-compose -f docker-compose.local.claude.yml up
```
Anthropic doesn't offer embedding models, so this config still uses local Ollama (`nomic-embed-text`) for embeddings — only the chat LLM is swapped to `claude-sonnet-4-6`. `.env` is gitignored; never commit your real API key.

## About the shared `./storage` volume
Both compose files bind-mount the same host folder, `./storage`, to `/app/server/storage` in the container. That's intentional:

* `container_name: anythingllm` and port `3001:3001` are the same in both files, so you can only ever run one of them at a time — there's no risk of two containers writing to `./storage` at once.
* Since they share `./storage`, switching between the MCP and non-MCP compose files keeps all your chats, workspaces, documents, and the LanceDB vector data intact. You're just toggling whether an MCP server is wired in, not starting over with a fresh instance.
* The MCP server list itself does **not** live inside `./storage`. `docker-compose.local.mcp.yml` bind-mounts a single file on top of it (`./my_hello_mcp/my_hello_mcp.json` → `/app/server/storage/plugins/anythingllm_mcp_servers.json`), so the MCP config is layered in from outside and never written back to `./storage/plugins/` on the host. When you run `docker-compose.local.yml` instead, that mount is gone and AnythingLLM just sees whatever (if anything) is already at `./storage/plugins/anythingllm_mcp_servers.json` — typically no MCP servers configured.

`./storage` is gitignored and should stay that way — it holds your actual runtime state (chat history, uploaded documents, the LanceDB vector store, downloaded models) plus `storage/comkey/ipc-priv.pem`, a private key generated by AnythingLLM. None of that belongs in version control; the compose files just point at this folder so your data survives container restarts.

## How to use mcp server
* setup local mcp server with json and put it into container using docker-compose.yml
```
{
  "mcpServers": {
    "my-local-hello-mcp": {
      "command": "python3",
      "args": ["/app/hello_local_mcp_server.py"],
      "env": {
        "ANY_REQUIRED_KEY": "your_value"
      }
    }
  }
}
```

* my the mcp server I have is based on python
```
docker exec -u root -it ${CONTAINER_ID} bash
apt-get update
apt-get install -y python3-pip
pip3 install mcp --break-system-packages
```
